# 方法说明

更新：2026-10-16（晚）。本文说明系统各部分“怎么做、为什么这样做”，以及 2026-10-14 至 10-16 改过的地方（标“改动”）。问题的发现与排查过程见 [engineering-log.md](engineering-log.md)，问题清单见 [BUGS.yaml](BUGS.yaml)。

## 1. 总原则

1. **模型只做需要理解和取舍的事**：理解任务、选择复核策略、看图判断、写处理建议、排障推理。
2. **必须可靠的事由程序做**：坐标、航线、电量、统计数字、安全校验、飞行控制。
3. **安全员有否决权**：确定性规则，任何角色不能推翻；所有飞行入口（巡检、排障、录制）都要先通过安全校验和飞行前检查。
4. **任何结论都要有评测**：每个改动跑全部回归（单元测试、100 个随机布局、规划 20 题），新能力配新评测。

## 2. 飞行控制

| 方法 | 做法 |
| --- | --- |
| 指令优先权（改动） | 飞控层统一拦截：飞控返航接管后，或当前任务已取消时，起飞、航点、云台等普通指令一律拒绝；正在等待到达的指令也会立即结束。只有返航和降落可以执行。之前取消只改数据库状态，靠各节点自己检查，返航后原任务仍可能继续发航点 |
| 取消与一键返航（改动） | 取消：停止普通指令，然后由程序沿安全航线返航。一键返航：交给飞控自带返航，任务只等待落地，不再发任何指令 |
| 起飞只成功一半（改动） | 返航节点以飞控遥测（在空中或已解锁）为准，不再只看“起飞成功”标记 |
| 订阅超时（改动） | 等待飞控就绪、等待云台列表都有真正的截止时间，超时按故障处理并返航；飞控自检改为常驻订阅、缓存最新结果 |
| 单执行实例（改动） | 确认接口只有条件更新成功才恢复执行，另有执行实例登记，同一任务同时只允许一个 |

## 3. 安全员

**计划校验**：电子围栏（多边形，航段每米抽样）、禁飞区（点和航段都检查，余量 3 米）、障碍物净空（水平 3 米，或高出 3 米）、限高、电量余量（按实测标定的各段耗时乘 1.2 倍保守系数）。

**飞行前检查**（规划通过后、每个架次起飞前各一次）：

| 检查项 | 规则 | 说明 |
| --- | --- | --- |
| 飞控自检 | 传感器校准、本地与全球位置估计、起飞点 | 真机同样适用 |
| 传感器超时 | 最近 60 秒飞控没有报传感器超时或故障 | 真机同样适用 |
| 仿真速度 | 不低于真实时间的 60%（低于 85% 提示） | 仅仿真 |
| 位置估计 | 飞控估计位置与仿真真实位置之差：水平 2.5 米、高度 1.5 米 | 仅仿真；真机对应 RTK 或视觉定位交叉校验 |
| 电脑负载 | 只提示 | 实测压到负载 34 仿真速度仍 99%，不能作为拦截依据 |
| 天气（改动，新增） | Open-Meteo 实时数据：平均风速 10 米/秒、阵风 12 米/秒、降水 0.2 毫米、雷暴、能见度 1500 米 | 仿真中只提示；`WEATHER_ENFORCE=1` 时拦截，取不到数据也拦截 |

**飞行中**：每次拍照比较估计位置与真实位置，超限即中止返航；近照里没有目标板时重新对准一次。

**其他飞行入口（改动）**：
- 排障试飞：航线先过安全员规则，按东、北、西、南选第一个安全的横移方向，都不安全就不执行；
- 场景录制：先展开含绕行的完整航线并校验，等飞控就绪、通过飞行前检查后才起飞，出错即返航。

## 4. 航线规划

| 方法 | 做法 |
| --- | --- |
| 随机场地 | 围栏形状、禁飞区、阵列数量 / 位置 / 朝向 / 行列、树都随种子变化；拒绝采样保证每列拍摄点可用 |
| 拍摄点 | 沿板面法线退后 20 米（按阵列偏角计算），机头正对阵列；近照在同一位置转向变焦 |
| 绕行（默认） | 直飞会进入禁飞区余量范围时，在 2 米栅格上做 A* 搜索，再按视线可达化简成尽量少的拐点；返航段同样处理 |
| 可见性图（改动，新增对比） | 禁飞区膨胀圆的外切正十二边形顶点加起终点建图，Dijkstra 求最短路径。100 个随机场地上与栅格 A* 对比：两者都 100% 通过，总长只短 0.6%，平均拐点多 0.56 个。多旋翼每个拐点都要减速，所以默认仍用栅格 A* |
| 不采用的方法 | Hybrid A*（多旋翼没有转弯半径约束）；B 样条 + ESDF 轨迹优化（静态已知地图、圆形禁飞区，投入产出不成比例；轨迹平滑由 PX4 位置控制器负责） |

## 5. 巡检判断

1. **哪块板在照片里，由几何决定**：拍摄瞬间的相机位姿（机体 × 云台 × 传感器）把每块板的四个角投影到照片上，裁切并校正为正视图，拼成带编号的拼图交给视觉模型。
2. **污损判断规则（改动，P2）**：不透明的小斑点也算污损（优先级最低但要报）；整片均匀的灰尘也算污损，并写明与反光的区别。效果：仿真随机布局全部复核检出 96.8% → 100%（轻微缺陷 91.7% → 100%），精确率 100% → 96.9%；真实照片灰尘 3/16 → 6/16，干净板误报 1/18 → 2/18。取舍：漏掉真缺陷比多一次现场确认代价大，所以保留。
3. **变焦分段拍整列（改动，新增，默认开启）**：广角整列照片里每块板只有约 52 像素，细小裂纹看不出来，初筛漏掉的缺陷在默认策略下不会有近照，等于最终漏检。现在每列拍完广角照片后，在同一拍摄点用变焦相机分段拍摄：规划时按相机几何预测每个对准点能完整拍到哪些板（画面四边各收窄 10%，5 个场景 1025 次预测零错误），贪心选最少的对准点覆盖全列；拍完核对每块板是否真的拍全，没拍全的补拍；分段都没拍全的板退回用广角照片。初筛用分段照片里约 200 像素的板块图。“全部复核”策略不做分段（逐块近照已覆盖）。效果与代价见第 9 节和工程日志 38。开关 `SEGMENT_SCREEN`。
3. **初筛规范化（改动）**：初筛和复核共用同一套状态规范化，无法识别的状态判为“不确定”，不会被丢弃；模型输出结构不对时，整张拼图的板都判为“不确定”交给复核。
3. **复核裁决（改动）**：复核结论无法识别判为“不确定”，绝不默认正常；初筛很确定、复核却判正常（或复核不确定）时再看一次，以第二次为准。再看一次时默认不开推理（`VISION_THINKING_RECHECK`，可开）。recheck 评测（12 个场景，按实时流程：一眼可见的缺失直接确认、不复核）：触发 107 次，全部是初筛误报、复核本来就判对，不开推理、同样请求再看、开推理再看三种做法结论完全相同。第一版评测漏了“缺失直接确认”这条，误以为开推理能多纠正 2 块（工程日志 37）。
4. **初筛失败（改动）**：模型不可用时，该列标为“未完成判断”，不计入已检查，报告单独列出，不再写“没有发现缺陷”。
5. **本地初筛分类器（改动，新增，默认关闭）**：
   - 训练数据：仿真录制的整列照片，按位姿裁出每块板，标签取场景生成器的标准答案，不需要人工标注；
   - 特征：亮度、梯度、亮线与暗斑比例、4×4 分块局部异常，并减去同一张照片所有板的中位数以抵消光照差异；
   - 模型：梯度提升树（scikit-learn）；
   - 阈值：只用训练场景的留一场景交叉验证结果选取；
   - 结果：没见过的 5 个场景 AUC 0.92，缺陷 100% 保留时少送 17%–28% 的板；真实调用视觉模型对比，初筛费用省约 19%，但标出的缺陷 37/42 对 38/42，差异来自视觉模型自身的判断波动。收益不明显，所以默认关闭（`TRIAGE_ENABLED=1` 开启）。

## 6. 报告

- **改动**：结论中的事实与数字全部由程序生成（巡检了哪些列、多少块板、确认几块、各类型数量、未确认、排除、未完成判断的列、异常）；
- 报告员（模型）只写处理建议，建议里不允许出现任何数字（含汉字数字）和数据里没有的板编号，否则丢弃并改用程序按优先级生成的建议，被丢弃的原文记入事件；
- **“哪几列问题集中”由程序统计（改动）**：输入里给出“破碎和缺失最集中的列”，报告员说集中时只能用这一项。评测发现模型自己从清单里数经常数错，完整清单也会错；
- **缺陷多时压缩清单（改动）**：保留同一优先级内置信度最高的前 12 条，另附全部条目按列和类型的数量。最初保留的是“按编号排序的前 12 条、其余汇总”，模型就从这 12 条里推断出 A 列最集中，而 A 列只是编号靠前；
- 建议里“A、D 两列”这样复述列编号的数量词，检查前规整为“A、D 列”，不因此整条拒收；
- 评测（reporter，按真实场地编号造 20 / 40 / 77 个缺陷 × 5 个种子）：修复后完整清单与压缩后都是“哪几列集中”说错 0 次、优先清单前列全是破碎与缺失、全部交代了未确认疑似，各拒收 1 次（建议里写了“一次”“一处”）；压缩后输入 Token 少 46%；
- HTML 报告每个缺陷附整列照片中的位置框和近照。

## 7. 排障

1. 先确认试飞空间安全（见第 3 节），再注入演示故障（只在演示和评测时）；
2. 基线试飞：起飞 8 米、悬停、横移 6 米、转向 90°、爬升 4 米、降落，记录日志指标；
3. 与已知良好配置（PX4 固件默认值）对比参数；差异里混有无害修改；
4. 诊断员提出假设，一次恢复一组参数重飞，用指标前后对比确认；
5. **改动**：无论成功、失败、取消、模型不可用，都先让飞机落地，再恢复良好配置。

## 8. 真实场地与数字孪生（改动，新增）

**坐标系原则**：仿真、飞控、安全员、评测内部一律 WGS-84；只在两个交接点换算：百度地点检索的 GCJ-02 → WGS-84（进入系统时），以及网页叠加百度底图时 WGS-84 → GCJ-02 → BD-09（显示时，所有要素用同一组参数）。境外不偏移。

| 步骤 | 做法 |
| --- | --- |
| 查坐标 | 百度地点检索（服务端 AK，SN 签名），返回 GCJ-02，迭代反解为 WGS-84（换算公式本身误差约 1–2 米） |
| 地物 | OpenStreetMap：Overpass 查询（多镜像、退避重试），失败时用官方地图数据接口；按位置缓存。水面、建筑为禁止区域，光伏电站轮廓为优先区域，建筑与单棵树为障碍物 |
| 高程 | Copernicus DEM GLO-30（1°×1° 瓦片下载缓存，双线性插值），生成相对起飞点的高程网格 |
| 起飞点 | 落在水面或建筑上时，移到 80 米内最近的空地，地物坐标同步平移 |
| 安全员 | 有高程的场地按离地高度检查下限与上限；障碍物顶部高度加上所在地面高度 |
| 飞控原点 | 跟随当前仿真场景（修复前固定为 PX4 默认坐标，真实场地无法起飞，被飞行前检查拦下） |
| 网页底图 | 后端用精确公式换算原点和东、北两个点，得到“每米对应多少度”（含 BD-09 公式高频项带来的约 1.5% 斜切），网页所有要素都用这组参数；±150 米内与逐点精确换算相差约 0.12 米（有单元测试） |
| 不做的 | Mapbox（国内可访问性不确定）；仿真地面贴真实影像（国内影像不允许下载，境外开放影像 10 米分辨率价值低） |

## 9. 评测方法

| 评测 | 方法 | 是否调用模型 |
| --- | --- | --- |
| 随机布局 | 100 个种子 × 三种复核策略，展开航线、分架次，交给安全员校验 | 否 |
| 绕行对比 | 同上的航线中找出所有需要绕行的航段，两种方法分别求解并校验 | 否 |
| 任务理解与规划 | 20 道题 × 2 轮：普通任务、保留电量、英文、不存在的编号（应追问）、越权请求（应拒绝） | 是 |
| 巡检复核策略 | 录制场景的全部照片后离线回放，与实时任务共用判断规则 | 是 |
| 本地初筛分类器 | 按场景划分训练 / 测试，阈值只在训练场景上选；`--replay` 对测试场景真实调用视觉模型对比 | `--replay` 时是 |
| 真实照片 | 公开数据集 645 张现场照片（6 类），与实时任务相同的判断说明，按类别统计；用来衡量“仿真里调出来的规则”迁移到真实照片的程度 | 是 |
| 数字孪生 | 5 个真实地点 × 10 个种子，同一种子比较随机布置与孪生约束布置：阵列压在水面 / 建筑上的比例、安全校验（含离地高度） | 否 |
| 排障 | 4 个注入故障，每个混入改动幅度更大的无害修改；对比“改得最多的就是原因”的规则基线 | 是 |
| 单元测试 | 67 个，包括异常与并发路径（起飞只成功一半、取消竞争、订阅不返回、重复确认、模型输出异常） | 否 |

- **初筛与近照选择的一组实验（2026-10-17，工程日志 38）**：screen（拼图板数、是否写证据）、zoom（把近照缩小模拟不同焦距）、cascade（初筛 + 本地分类器）、segments（变焦分段，按实时流程走完）。分段拍摄在 12 个没参与任何调整的新场景（84 个缺陷）上：检出 73.8% → 96.4%，精确率 100%，近照 10.8 → 11.6 张 / 场景，估计飞行 3.3 → 4.1 分钟；全部拍近照 100%、5.7 分钟。

## 11. 模型费用（改动）

- **原因**：视觉模型开着推理时，每次平均输出约 960 Token，其中约 90% 是推理过程，而结论 JSON 只需约 80 Token；输出单价是输入的 4 倍，北京时间高峰时段单价是闲时的 2 倍。
- **做法**：对照实验（同一模型、同一批图片）比较推理全开、只在初筛开、全关三种方案后，默认关闭推理（`VISION_THINKING=off`）。关闭推理时设置输出上限作为保险；开着推理时不设上限，避免把推理算进上限导致 JSON 被截断。
- **结果**：费用省 75%–86%，近照复核后的检出率、精确率不变；实时任务每次巡检约 ¥0.056（92 块板），飞行时间缩短约 30%。
- **评测工具**：Token 用量统计（按高峰、闲时两种单价折算）、完全相同请求的结论缓存（`--cache`，规则和模型不变时重跑零费用）、高峰时段提示。
- **运行成本与研发成本分开**：运行成本按每块板计（约 ¥0.0006），研发评测成本随迭代次数增长，用缓存和抽样控制。
