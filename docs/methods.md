# 方法说明

更新：2026-10-16。本文说明系统各部分“怎么做、为什么这样做”，以及 2026-10-14 至 10-16 改过的地方（标“改动”）。问题的发现与排查过程见 [engineering-log.md](engineering-log.md)，问题清单见 [BUGS.yaml](BUGS.yaml)。

## 1. 总原则

1. **模型只做需要理解和取舍的事**：理解任务、选择复核策略、看图判断、写处理建议、排障推理。
2. **必须可靠的事由程序做**：坐标、航线、电量、统计数字、安全校验、飞行控制。
3. **安全员有否决权**：确定性规则，任何角色不能推翻；所有飞行入口（巡检、排障、录制）都要先通过安全校验和飞行前检查。
4. **任何结论都要有评测**：每个改动跑全部回归（单元测试、100 个随机布局、规划 20 题），新能力配新评测。

## 2. 飞行控制

| 方法 | 做法 |
| --- | --- |
| 指令优先权（改动） | 飞控层统一拦截：飞控返航接管后，或当前任务已取消时，起飞、航点、云台等普通指令一律拒绝；正在等待到达的指令也会立即结束。只有返航和降落可以执行。之前取消只改数据库状态，靠各节点自己检查，返航后原任务仍可能继续发航点 |
| 取消与一键返航（改动） | 取消：停止普通指令，然后由程序沿安全航线返航。一键返航：交给飞控自带返航，任务只等待落地，不再发任何指令 |
| 起飞只成功一半（改动） | 返航节点以飞控遥测（在空中或已解锁）为准，不再只看“起飞成功”标记 |
| 订阅超时（改动） | 等待飞控就绪、等待云台列表都有真正的截止时间，超时按故障处理并返航；飞控自检改为常驻订阅、缓存最新结果 |
| 单执行实例（改动） | 确认接口只有条件更新成功才恢复执行，另有执行实例登记，同一任务同时只允许一个 |

## 3. 安全员

**计划校验**：电子围栏（多边形，航段每米抽样）、禁飞区（点和航段都检查，余量 3 米）、障碍物净空（水平 3 米，或高出 3 米）、限高、电量余量（按实测标定的各段耗时乘 1.2 倍保守系数）。

**飞行前检查**（规划通过后、每个架次起飞前各一次）：

| 检查项 | 规则 | 说明 |
| --- | --- | --- |
| 飞控自检 | 传感器校准、本地与全球位置估计、起飞点 | 真机同样适用 |
| 传感器超时 | 最近 60 秒飞控没有报传感器超时或故障 | 真机同样适用 |
| 仿真速度 | 不低于真实时间的 60%（低于 85% 提示） | 仅仿真 |
| 位置估计 | 飞控估计位置与仿真真实位置之差：水平 2.5 米、高度 1.5 米 | 仅仿真；真机对应 RTK 或视觉定位交叉校验 |
| 电脑负载 | 只提示 | 实测压到负载 34 仿真速度仍 99%，不能作为拦截依据 |
| 天气（改动，新增） | Open-Meteo 实时数据：平均风速 10 米/秒、阵风 12 米/秒、降水 0.2 毫米、雷暴、能见度 1500 米 | 仿真中只提示；`WEATHER_ENFORCE=1` 时拦截，取不到数据也拦截 |

**飞行中**：每次拍照比较估计位置与真实位置，超限即中止返航；近照里没有目标板时重新对准一次。

**其他飞行入口（改动）**：
- 排障试飞：航线先过安全员规则，按东、北、西、南选第一个安全的横移方向，都不安全就不执行；
- 场景录制：先展开含绕行的完整航线并校验，等飞控就绪、通过飞行前检查后才起飞，出错即返航。

## 4. 航线规划

| 方法 | 做法 |
| --- | --- |
| 随机场地 | 围栏形状、禁飞区、阵列数量 / 位置 / 朝向 / 行列、树都随种子变化；拒绝采样保证每列拍摄点可用 |
| 拍摄点 | 沿板面法线退后 20 米（按阵列偏角计算），机头正对阵列；近照在同一位置转向变焦 |
| 绕行（默认） | 直飞会进入禁飞区余量范围时，在 2 米栅格上做 A* 搜索，再按视线可达化简成尽量少的拐点；返航段同样处理 |
| 可见性图（改动，新增对比） | 禁飞区膨胀圆的外切正十二边形顶点加起终点建图，Dijkstra 求最短路径。100 个随机场地上与栅格 A* 对比：两者都 100% 通过，总长只短 0.6%，平均拐点多 0.56 个。多旋翼每个拐点都要减速，所以默认仍用栅格 A* |
| 不采用的方法 | Hybrid A*（多旋翼没有转弯半径约束）；B 样条 + ESDF 轨迹优化（静态已知地图、圆形禁飞区，投入产出不成比例；轨迹平滑由 PX4 位置控制器负责） |

## 5. 巡检判断

1. **哪块板在照片里，由几何决定**：拍摄瞬间的相机位姿（机体 × 云台 × 传感器）把每块板的四个角投影到照片上，裁切并校正为正视图，拼成带编号的拼图交给视觉模型。
2. **初筛规范化（改动）**：初筛和复核共用同一套状态规范化，无法识别的状态判为“不确定”，不会被丢弃；模型输出结构不对时，整张拼图的板都判为“不确定”交给复核。
3. **复核裁决**：复核结论无法识别判为“不确定”，绝不默认正常；初筛很确定、复核却判正常时再看一次，以第二次为准。
4. **初筛失败（改动）**：模型不可用时，该列标为“未完成判断”，不计入已检查，报告单独列出，不再写“没有发现缺陷”。
5. **本地初筛分类器（改动，新增，默认关闭）**：
   - 训练数据：仿真录制的整列照片，按位姿裁出每块板，标签取场景生成器的标准答案，不需要人工标注；
   - 特征：亮度、梯度、亮线与暗斑比例、4×4 分块局部异常，并减去同一张照片所有板的中位数以抵消光照差异；
   - 模型：梯度提升树（scikit-learn）；
   - 阈值：只用训练场景的留一场景交叉验证结果选取；
   - 结果：没见过的 5 个场景 AUC 0.92，缺陷 100% 保留时少送 17%–28% 的板；真实调用视觉模型对比，初筛费用省约 19%，但标出的缺陷 37/42 对 38/42，差异来自视觉模型自身的判断波动。收益不明显，所以默认关闭（`TRIAGE_ENABLED=1` 开启）。

## 6. 报告

- **改动**：结论中的事实与数字全部由程序生成（巡检了哪些列、多少块板、确认几块、各类型数量、未确认、排除、未完成判断的列、异常）；
- 报告员（模型）只写处理建议，建议里不允许出现任何数字（含汉字数字）和数据里没有的板编号，否则丢弃并改用程序按优先级生成的建议，被丢弃的原文记入事件；
- HTML 报告每个缺陷附整列照片中的位置框和近照。

## 7. 排障

1. 先确认试飞空间安全（见第 3 节），再注入演示故障（只在演示和评测时）；
2. 基线试飞：起飞 8 米、悬停、横移 6 米、转向 90°、爬升 4 米、降落，记录日志指标；
3. 与已知良好配置（PX4 固件默认值）对比参数；差异里混有无害修改；
4. 诊断员提出假设，一次恢复一组参数重飞，用指标前后对比确认；
5. **改动**：无论成功、失败、取消、模型不可用，都先让飞机落地，再恢复良好配置。

## 8. 真实场地（改动，新增）

| 步骤 | 做法 |
| --- | --- |
| 查坐标 | 百度地点检索（服务端 AK，SN 签名），请求返回国测局坐标（GCJ-02） |
| 换算 | GCJ-02 → WGS-84：正算公式迭代反解，相对正算误差厘米级；正算公式本身与真实偏移相差约 1–2 米 |
| 场地 | 原点放在真实经纬度；阵列、禁飞区、树仍按种子随机布置 |
| 地面 | 有 Mapbox Token 时取以原点为中心的卫星影像（按纬度计算缩放级别，使影像边长等于地面边长），铺进 Gazebo 地面并作网页底图；没有时用程序生成的草地贴图 |
| 天气 | 飞行前检查按真实位置取天气 |
| 国外地点 | 百度没有可靠数据，命令行直接给经纬度 |

## 9. 评测方法

| 评测 | 方法 | 是否调用模型 |
| --- | --- | --- |
| 随机布局 | 100 个种子 × 三种复核策略，展开航线、分架次，交给安全员校验 | 否 |
| 绕行对比 | 同上的航线中找出所有需要绕行的航段，两种方法分别求解并校验 | 否 |
| 任务理解与规划 | 20 道题 × 2 轮：普通任务、保留电量、英文、不存在的编号（应追问）、越权请求（应拒绝） | 是 |
| 巡检复核策略 | 录制场景的全部照片后离线回放，与实时任务共用判断规则 | 是 |
| 本地初筛分类器 | 按场景划分训练 / 测试，阈值只在训练场景上选；`--replay` 对测试场景真实调用视觉模型对比 | `--replay` 时是 |
| 排障 | 4 个注入故障，每个混入改动幅度更大的无害修改；对比“改得最多的就是原因”的规则基线 | 是 |
| 单元测试 | 65 个，包括异常与并发路径（起飞只成功一半、取消竞争、订阅不返回、重复确认、模型输出异常） | 否 |
