# 2026-10-17 夜间计划：人工测试反馈修复 + 应急救援场景

来源：负责人的人工测试文档 `docs/人工测试.docx`（40 条反馈 + 9 张截图）。负责人睡觉期间自主执行，醒来交付。

**规则（防跑偏）**
- 按批次做，每批只做同一类问题；每批结束：自测（浏览器实际操作 + pytest + 构建）→ 勾选本文件 → 记 BUGS → 提交推送；
- 每批开始前重读本文件的“当前批次”和“决策记录”；
- 功能性错误记 BUGS.yaml（DR-058 起）；体验类问题在本文件的对照表里勾选，不进 BUGS；
- 光伏流程的准确率不能退步：改动视觉、场景贴图后要跑评测；
- 所有界面改动要考虑之后会有多个应用场景（光伏、救援……）：任务、场景、报告、评测都按“场景类型”组织，不写死“列、板”。

## 决策记录

| 决定 | 理由 | 否掉的方案 |
| --- | --- | --- |
| 主界面改为“工作台”：左侧新任务 + 历史任务（可搜索、按场景类型筛选），右侧当前任务的地图、实时视角、进度、结果，同一页面；其他页面（场景库、用量、评测、设置、说明）放进窄导航栏 | 负责人希望像成熟的 Agent 平台；任务是核心对象，来回切页面是主要不顺手的地方 | 保留多页面只改样式：解决不了“看不到进度、历史记录分散” |
| 一台仿真飞机同一时间只执行一个任务；可以连续下达，新任务排队，按顺序执行；每个任务的上下文独立（LangGraph 线程号 = 任务号） | 物理上只有一架飞机；排队解决“想一次下多个任务”；上下文放一起会互相污染 | 并行执行多个任务：需要多机仿真，留到以后 |
| 地点搜索：国内用百度联想（suggestion），国外用 Photon（基于 OpenStreetMap 的联想检索）；去掉城市输入框 | 百度检索国外地名会返回国内同名商户（Melbourne → 上海餐厅） | Nominatim：使用政策禁止联想式请求 |
| “种子”改称“布局编号”，默认随机、收进高级选项 | 普通用户不理解种子；只保留一个“生成场景”按钮 | — |
| 场景库顶部固定操作栏：选中场景后只有一个“启动仿真”按钮；卡片按创建时间倒序、分页、按类型筛选 | 每张卡片都有启动按钮重复、且操作完要滚回顶部 | — |
| 仿真启动改为后台进行、立刻返回，界面按阶段显示进度（飞控 → 仿真器 → 相机 → 飞行前检查） | 原来请求要等 30 秒以上，期间按钮全灰、取消后不恢复 | — |
| 飞行前检查：显示检查时间、手动刷新按钮，并写明“不调用模型、不花钱”；仿真停止时立即清空 | 负责人担心刷新花 token；停止仿真后显示过期的结果 | — |
| 模型费用：评测的模型调用也入库，用量页按“任务 / 评测 / 合计”和北京时间日期汇总（接口按北京时间计费） | 页面只统计任务、不含评测，和接口账单对不上 | — |
| 设置页：视觉模型推理、分段拍摄等开关在网页上可改，保存后立即生效 | 负责人找不到推理开关 | 只写在 .env：普通用户改不了 |
| 前端低耦合：接口调用集中在 `api/`（按领域分文件）；共享状态放在按领域拆分的 composable（仿真、任务、场景、设置），组件只接收属性、发出事件；应用场景的差异（术语、示例任务、图例、结果卡片）集中在一张场景注册表，页面按注册表渲染，不写死“列、板” | 负责人要求，便于维护和接入多个场景；另一个审查 Agent 会做代码审查 | 页面里直接调接口、到处判断场景类型 |
| 应急救援：人员会走动、可能在水中、有路人干扰；用任务描述里的特征（衣服颜色等）区分要找的人和路人 | 负责人要求贴近真实 | 只放静止目标：不真实 |
