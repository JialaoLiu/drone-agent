## 三、应急救援

**场景**：公园（湖面、步道、树、码头等地标），1 个走失目标（成人或儿童，可能走动、静止或落水），5–10 个路人（约三成穿同色上衣），1–2 件地上的同色衣物；真实场地的地面铺卫星影像。人物是程序生成的人形，由相机桥按路线移动。

**流程**：与光伏共用调度员、规划员、安全员、人工确认、飞手、报告员。程序先在俯视照片里找颜色异常的小块，再交给模型判断“是不是人、穿什么、在不在水里”，位置由程序用相机位姿算出；相符的用变焦原地确认，变焦里没看到人就飞到上方降低高度用广角重找。

**端到端评测**（通过网页同一套接口：生成场景 → 启动仿真 → 下达任务 → 对照答案；6 个随机场景 + 文翰湖真实场地，同一版代码）：

| 指标 | 结果 |
| --- | --- |
| 找到 | 5/7（静止 2/2、落水 2/2、走动 1/2；另 1 个场景启动后飞行前检查没通过，未能开始） |
| 错认（把路人或衣物确认为目标） | 0 |
| 定位误差 | 平均 0.15 米 |
| 找到时用时 | 平均 108 秒 |
| 每次模型费用 | 约 ¥0.0055 |

三轮迭代都是“看失败照片 → 找原因 → 改规则”，从 3/7 到 4/7 再到 5/7：

1. **落水者被当成路人**：模型看到“水面露出头肩”，却因为“上衣偏灰”排除了。衣服泡在水里本来就看不清颜色，改为水里有人就去确认、按落水者上报；
2. **年龄看不出就不确认**：改为模型只报告衣着和是否小孩，由程序比对；另外排除了无人机自己的影子（它被当成候选、浪费确认次数）；
3. **走动的人追不上**：从发现到变焦对准要十来秒，人已经走出约 4 米宽的变焦画面。改为飞到正上方、降到低空用广角拍，再找离上次位置最近的人。

**还没解决**：穿绿色上衣站在草地上的人，程序不把它列为候选；目标走出搜索半径时一张都拍不到。样本只有 7 个场景，只能说明“能工作、方向对”。

**评测过程中顺带找到并修复的两个真问题**（都影响你的日常使用）：

- 切换场景后飞行前检查一直超时（DR-064）；
- 切换场景后下任务，飞机不起飞、任务挂住（DR-065）。

现在所有飞控指令都有 12 秒上限，出问题会以明确原因失败并释放飞机，不会再挂住。
