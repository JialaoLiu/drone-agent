# 下一步计划与场景分批

更新：2026-10-14。不着急，按批次推进；每一批都要做到可运行、有评测、有文档，再开始下一批。

## 原则

1. **先骨架，后场景。** 把光伏巡检整理成第一个“场景包”，之后每个新场景只需提供：场地生成器、目标与标准答案、挂载的传感器、巡检员判断规则、评测指标。调度、规划、安全员、人工确认、飞手、报告员全部复用。
2. **每批只做 1–2 个场景，做深。** 一个场景要有随机种子、回测和对照基线，宁可少，不做只能演示一次的浅场景。
3. **如实写局限。** 仿真渲染与真实图像有差距，每个场景都要说明哪些结论只在仿真中成立。

## 外部升级建议的审阅（2026-10-16）

另一份升级草案建议依次做 Hybrid A\*、自动优化提示词、B 样条 + ESDF 轨迹、多机协同。审阅结论：
- 不做 Hybrid A\*：多旋翼可悬停、原地转向，没有最小转弯半径；现有绕行在网格 A\* 后已做视线平滑，平滑与加减速由 PX4 位置控制器负责。
- 不做 B 样条 + ESDF：地图静态已知、禁飞区为圆，投入产出不成比例。
- 不做提示词自动优化：规划评测稳定 20/20，题量太少，优化只会过拟合。
- 多机协同暂缓：先做离线分区分配与机间间隔校验，再考虑实时。
- 改做：可见性图精确绕行（网格 A\* 兜底，100 种子 A/B 对比）；视觉评测扩展到随机布局。

## 成本优化（2026-10-16；第 1–3 项已完成，见下方实测）

**现状**：视觉模型每次调用平均输出 959 Token，我们只需要约 80 Token 的 JSON，约 90% 的费用花在输出（推理过程）上；高峰时段单价是闲时的 2 倍。一次巡检 ¥0.06–0.27（每块板约 ¥0.002–0.003）；一次完整真实照片评测 ¥4.6（645 张，高峰时段）。

**按收益排序的做法**：

| 顺序 | 做法 | 依赖 | 预期 |
| --- | --- | --- | --- |
| 1 | 压缩输出：限制最大输出长度、关闭或缩短推理（看接口支持）、依据字段限一句话、结构化输出 | 无 | 最大的一块，先测“不推理时准确率掉多少” |
| 2 | 评测放在北京时间闲时运行 | 无 | 单价减半 |
| 3 | 评测结果缓存：按图片哈希 + 提示词版本 + 模型版本缓存回答 | 无 | 提示词和模型不变时重跑零费用 |
| 4 | 分层评测：日常 60 张左右的分层抽样，发布前全量 | 无 | 日常回归费用降一个数量级 |
| 5 | 判别式分类器（预训练图像特征 + 线性头）替换现在的手工特征分类器，做第一级过滤 | 横向对比实验 | 现有手工特征 AUC 0.92；预训练特征有望更高，且训练、推理都很轻 |
| 6 | 本地小视觉模型做第二级（只在分类器拿不准时调用），云端模型兜底 | 实测准确率与延迟 | 云端调用从“每块板”降到“少数板” |
| 7 | 每日预算上限与超限告警 | 无 | 防止失控 |

**对另一份“本地模型”方案的评估**（另一个 Agent 的建议，L3 级参考）：
- 同意：费用的根因是输出推理而不是看图；第 1–4 条不依赖任何选型，应该先做；闭集分类更适合判别式模型；小视觉模型只适合做过滤器，不适合做最终裁决；先做横向对比实验再定架构。
- 需要更正：本项目现有的分类器是 scikit-learn 的手工特征加梯度提升树，不是 torchvision；本项目也没有在用 SigLIP 做画面向量，“复用现成基础设施”这一点不成立（需要新引入）。
- 关于这台 M4 16 GB：2B 参数的 4 位量化模型内存约 1.5–2 GB，单独跑可行；但实时任务时 PX4、Gazebo（占用 GPU 渲染相机）、后端同时运行，本地视觉模型会和仿真抢资源，可能拖慢仿真并触发飞行前检查的“仿真速度”不通过。所以本地视觉模型只用于离线评测；真实部署应放在带 GPU 的服务器上。判别式分类器很轻，实时任务中也能跑。
- 方案中列出的模型名、参数量、许可证我没有逐个核实，选用前要在模型页面确认许可证（尤其是 DINOv3 的自定义协议、Gemma 系列的专有协议）。

**建议的第一步**（约 1 天）：用已录制的 12 个仿真场景（约 960 块板，自动标注）和公开数据集，对比现有手工特征分类器与 1–2 种预训练特征分类器的准确率和延迟；同时测一次“关闭推理、限制输出长度”时云端模型准确率的变化。根据结果再决定是否引入本地小视觉模型。

**面试讲法要点**：把运行成本（计入服务价格，按每块板算单位成本）和研发评测成本（随迭代次数增长，真正的风险）分开；成本优化有路线：先用云端跑通并留下数据（录制回放已经是这个基础），再用积累的标注数据训练本地分类器挡掉大部分流量，云端只兜底，成本随规模下降。

### 实测结果（2026-10-16，同一个模型、同一批图片）

| 方案 | 随机布局 3 场景（31 个缺陷）费用 | 全部复核：检出 / 精确 / 类型 | 复核疑似：检出 / 精确 | 初筛误报 | 真实照片 95 张费用 | 真实照片核心四类检出 / 精确 |
| --- | ---: | --- | --- | ---: | ---: | --- |
| 推理全开（原默认） | ¥1.56 | 100% / 100% / 100% | 90.3% / 100% | 18 | ¥0.86 | 81.2% / 97.5% |
| 只在初筛开推理 | ¥1.07 | 100% / 100% / 96.8% | 93.5% / 100% | 22 | （同全关） | — |
| **推理全关（新默认）** | **¥0.39；第二次 ¥0.25** | 100% / 100% / 96.8%（两次相同） | 90.3% / 100%；第二次 93.5% / 100% | 30、32 | **¥0.12** | 79.2% / 97.4% |

费用都按高峰单价折算，便于比较。结论：
- 关闭推理后输出 Token 减少约 90%，费用省 75%–86%；近照复核后的检出率、精确率不变，代价是缺陷类型错 1 个，初筛误报变多（都会被复核纠正）；
- 钱主要花在初筛（10 块板一张拼图，推理很长），所以“只在初筛开推理”只省 32%，不划算；
- 实时任务验证（solar_46 全部 4 列）：11/11 检出、类型全对、1 个误报，¥0.056（原来 ¥0.12），飞行时间 237 秒 → 164 秒（模型回复更快，悬停等待变短）；
- 开关 `VISION_THINKING`：off（默认）、on、screen；评测加 `--thinking`、`--cache`，报告记录 Token 用量并按高峰、闲时两种单价折算；高峰时段运行评测会给出提示。
