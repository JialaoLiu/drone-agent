# 下一步计划与场景分批

更新：2026-10-14。不着急，按批次推进；每一批都要做到可运行、有评测、有文档，再开始下一批。

## 原则

1. **先骨架，后场景。** 把光伏巡检整理成第一个“场景包”，之后每个新场景只需提供：场地生成器、目标与标准答案、挂载的传感器、巡检员判断规则、评测指标。调度、规划、安全员、人工确认、飞手、报告员全部复用。
2. **每批只做 1–2 个场景，做深。** 一个场景要有随机种子、回测和对照基线，宁可少，不做只能演示一次的浅场景。
3. **如实写局限。** 仿真渲染与真实图像有差距，每个场景都要说明哪些结论只在仿真中成立。

## 当前状态（第 0 批，已完成）

- 光伏巡检：随机布局（围栏、禁飞区、阵列数量 / 朝向 / 行列、树）、A* 绕行、多架次换电池、四种复核策略；
- 评测：随机布局 100 个种子全部通过安全校验；巡检复核策略对比；任务理解与规划 20/20；排障 4/4（规则基线 0/4）；
- 网页 7 个页面：总览、巡检任务、任务详情、飞行排障、场景库、用量与成本、评测结果、使用说明；
- 操作手册：`docs/user-guide.md`。

## 第 3 批：森林防火（三山森林公园）

- 任务：沿地形巡逻，发现火点、烟、违规用火，复核后上报坐标与面积；
- 传感器：可见光加热成像（先验证 Gazebo 热成像相机在本机能否渲染）；
- 随机生成：火点位置与大小、烟、人员、假热源（车辆、屋顶反光）；
- 评测：检出率、误报、定位误差（米）、发现时间；外部验证数据集 FLAME 3（许可证待确认）。

## 第 4 批：应急救援（文翰湖公园）

- 任务：扩展方形或扇形搜索、人员发现、模拟投送（落点误差）、空中喊话、通信中继悬停点；
- 随机生成：落水或走失人员位置、姿态、遮挡；
- 评测：搜索覆盖率、发现时间、定位误差、投送落点误差；外部验证 SARD、HERIDAL（许可证待确认）。

## 第 5 批：电力红外测温

- 任务：杆塔与线路巡检，读取发热接头、绝缘子的温度与温升，按行业红外诊断规范分级（规范条款需查证后再写）；
- 评测：发热点检出率、温度读数误差、分级正确率；外部数据 InsPLAD 等。

## 第 6 批：测绘与实景三维、灭火救援数字化预案

- 依据文献笔记 `docs/research/2026-10-14-oblique-photogrammetry-fire-plan.md`：5 向倾斜航线，航向重叠 75%、旁向重叠 70%，按影像精度公式反算拍摄距离；
- 采集后自动检查覆盖与重叠是否达标，避免返工补拍；
- OpenDroneMap 重建，与仿真场景的真实几何比对误差；在模型上标注水源、消防通道、登高面；
- 评测：覆盖完整率、重叠达标率、重建误差、从下达任务到出模型的总时长。

## 第 7 批（可选）：环保监测、火山等特殊场景

- 环保：水质、大气。仿真只能用指数图，最弱；改用公开数据集演示（例如安大略湖无人机多光谱加实测水质数据），如实说明局限；
- 火山：热异常与气体羽流监测，与森林防火共用热成像链路；高海拔与强风下的飞行限制写成安全员规则。数据与规范需要先调研。

## 外部升级建议的审阅（2026-10-16）

另一份升级草案建议依次做 Hybrid A\*、自动优化提示词、B 样条 + ESDF 轨迹、多机协同。审阅结论：
- 不做 Hybrid A\*：多旋翼可悬停、原地转向，没有最小转弯半径；现有绕行在网格 A\* 后已做视线平滑，平滑与加减速由 PX4 位置控制器负责。
- 不做 B 样条 + ESDF：地图静态已知、禁飞区为圆，投入产出不成比例。
- 不做提示词自动优化：规划评测稳定 20/20，题量太少，优化只会过拟合。
- 多机协同暂缓：先做离线分区分配与机间间隔校验，再考虑实时。
- 改做：可见性图精确绕行（网格 A\* 兜底，100 种子 A/B 对比）；视觉评测扩展到随机布局。
